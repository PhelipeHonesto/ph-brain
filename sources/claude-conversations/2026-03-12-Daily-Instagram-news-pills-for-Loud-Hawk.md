"I want to build a daily Instagram news pill system for Loud Hawk. Currently I use AI to find aviation news and write captions, but I want to systematize it with better brand consistency and speed. Here's what I need:
1. A daily news pill format spec — based on our existing post templates, define exactly what each daily post looks like (headline, context, visual format)
2. A workflow for going from raw news source to finished post in under 10 minutes
3. How daily pills connect to the biweekly newsletter — some pills might become Quick Hits or seed a main piece
4. A content mix framework — not every day should be breaking news. Some days are market observations, some are educational, some are The Gap callouts
5. Eventually I want to build a Claude Code skill that takes a one-line news input and outputs the full post caption in Loud Hawk voice
I also want to integrate this with the newsletter repurposing — each edition should generate 3-4 Instagram posts (carousel and standard) in addition to the daily pills."

Here's the complete system. Eight sections covering everything you asked for, all grounded in your existing editorial framework. A few things worth flagging:

**The daily-to-newsletter pipeline is the most important part.** The whole point of running daily pills is that you never start a newsletter edition from scratch. Your best pills become Quick Hits, your deepest pill becomes the Main Piece seed, and your sharpest Market Signal pill becomes The Signal opener. The newsletter is an upgrade of work you've already done — not a separate project.

**The content mix framework is intentionally Gap-heavy.** Your post examples and LinkedIn performance data from the 60-Day Calendar both show The Gap is your sharpest editorial voice. It's overweighted at 30% on purpose — that's the lane people share and remember.

**On the Claude Code skill spec** — I wrote it as a detailed functional spec you can hand to Claude Code directly when you're ready to build it. The key constraint is the vague-input rejection: the skill should refuse to generate a caption if the input doesn't include at least one specific detail. That enforces the Editorial Blueprint's "be specific or be quiet" rule at the automation layer.

**One honest pushback on "daily":** Your Execution Memo and capacity constraints say 10–15 hours/week for all OSA activity. A true 7-day-a-week posting cadence will eat into that fast. The system is designed around 3–5 posts/week as the real target, with the framework to go daily only when the workflow is fully systematized and you're batching efficiently. Start at 3/week, get the workflow tight, then scale up.
