## Audit: SKILL.md

Solid. Four things to tighten:

**1. Script path mismatch.** The SKILL.md says `~/osa-marketing/.claude/skills/lh-carousel/scripts/generate_carousel.py`. Your actual disk structure from the project instructions is `~/Desktop/OSA/`. Either the script actually lives at the osa-marketing path (a separate marketing repo?) or this needs to be updated. If the script lives inside your OSA folder, fix the path. If osa-marketing is a real separate workspace, fine, but call that out in the skill so Claude Code doesn't guess.

**2. No ffmpeg dependency check.** The motion slides silently fail if ffmpeg isn't installed. The `gen_motion` function runs `subprocess.run(["ffmpeg", ...], capture_output=True)` and never checks the return code. If ffmpeg isn't there, you get empty output and no error message. Add a preflight check at the top of `main()` or in the skill instructions.

**3. The BEIGE constant is wrong.** BRAND.md defines beige as `#e4e4d3` which is RGB (228, 228, 211). The `.py` file uses `BEIGE = (228, 228, 211)`. That matches. But `#e4e4d3` is actually (228, 228, 211). Wait. `e4` = 228, `e4` = 228, `d3` = 211. Yes, matches. Scratch that, the color is correct.

**4. SKILL.md says "3 motion MP4s" but the slide arc shows S01, S02, S04 as motion.** That's three. Consistent. Good.

**5. No `--static-only` flag.** Would be useful for draft review. Right now if you don't have ffmpeg, the three motion slides silently produce nothing. A `--static-only` flag that renders the final frame of each motion slide as a PNG instead would let you review content without the full pipeline.

## Audit: generate_carousel.py

**Bug 1 (real): `draw_rule` is extremely slow.** Line 113-117 uses `putpixel` in a nested loop (6 rows x 936 cols = 5,616 individual pixel writes). For static slides this is merely slow. For motion slides this runs per frame (450 frames x 5,616 = 2.5M putpixel calls per motion slide). Replace with `ImageDraw.rectangle`:

```python
def draw_rule(img):
    d = ImageDraw.Draw(img)
    d.rectangle([72, 76, 72+936-1, 81], fill=ORANGE)
```

Same result, 100x faster. Same issue on the CTA slide bar (lines 422-424).

**Bug 2 (real): `alpha_text` creates a full 1080x1350 RGBA overlay per call.** In `gen_data`, this runs up to 6 times per frame (2 calls per data item x 3 items) x 90 animation frames = 540 full-size image allocations per motion slide. Heavy. Not a correctness bug but it will make motion generation very slow. For draft use this is fine. For production, consider drawing alpha text directly onto an RGBA image instead of compositing per call.

**Bug 3 (medium): `gen_stat2` line 330 passes a 4-tuple `(*BEIGE, 120)` to `draw.text`.** `ImageDraw.text` on an RGB image expects a 3-tuple. This works in Pillow because it silently ignores the alpha on RGB images, but it's technically incorrect and could break in future Pillow versions. Use `alpha_text` for those lines or convert to RGB tuple.

**Bug 4 (minor): bare `except: pass` everywhere.** If a font is missing or a JSON key is wrong, every slide generator silently produces a blank slide. Good for resilience, bad for debugging. At minimum, add `except Exception as e: print(f"WARNING: {e}")`.

**Bug 5 (minor): cover counter logic (lines 229-237) is fragile with non-numeric s1_number.** Your Capstone carousel uses `"1"` which works fine. But if someone passes `"#1"` or `"3rd"`, the prefix/suffix reconstruction logic will break. The `raw_num.index(c)` call on characters that appear multiple times is unreliable. For this specific carousel you're fine, but the counter animation only makes sense for pure numbers anyway.

**Missing: no `--static-only` mode.** Already noted above.
